2. CI / CD

Three workflows per repo: ci.yml, deploy.yml, ai-review.yml. API CI fails on missing migrations; apply happens on ECS task start. Only the API repo runs Terraform.

■ Staging

Trigger: merge to develop

  • Environment staging (no reviewers)
  • API TF: terraform/envs/staging
  • API + web ship together

■ Prod

Trigger: published Release (+ reviewers)

  • Environment prod (approval required)
  • API TF: terraform/envs/prod
  • First live 2026-08-10

API turboai-notes-api

  1. Build & push ECR Docker image → env repository
  2. Terraform apply stack + triage Lambda zip (archive_file)
  3. ECS force deploy new tasks → entrypoint migrate --noinput
  4. Smoke /api/health/

Migrate runs on task start (staging + prod), not in the CI unit-test job.

Web turboai-notes-web

  1. Next export next build static output
  2. S3 sync upload site bucket
  3. CloudFront invalidate purge CDN cache
  4. Smoke hit WEB_URL

No Terraform / no migrations — static site only; bucket from API stack.

Shared: Secrets → CI (incl. migration check) → OIDC. API: ECR → TF → ECS (entrypoint apply). Web: export → S3 → CloudFront.

6. Security

Why this design is hard to abuse — tokens never in JS, authz only on the API, origins and secrets locked per environment.

httpOnly JWT CSRF bootstrap CORS per env Authz in Django SM for secrets Bastion /32
Tokens

Static export is fine

  • Hosting choice: Next → S3 + CloudFront
  • JWTs are not in JS / localStorage
  • httpOnly · Secure · SameSite=None on the API origin
Cross-origin

CSRF + CORS locked

  • Unsafe methods need X-CSRFToken (bootstrap via /api/auth/csrf/)
  • CORS_ALLOWED_ORIGINS / CSRF_TRUSTED_ORIGINS = that env’s web CF only
  • No wildcards / localhost in staging or prod
Backend

Ownership stays in Django

  • Frontend has no authz / ownership rules
  • Django password validators + auth throttle 20/min
  • django-axes: 5 failures / 1h cooloff
Secrets

Two paths, on purpose

  • Django/DB: GH → TF → SM → ECS
  • MiniMax / Jira: SM only → triage Lambda
  • No secret values on this page
Network

Bastion + private RDS

  • Bastion SSH allowlisted to operator /32
  • RDS in private subnets (ECS + bastion only)
  • TLS at CloudFront; ALB is HTTP inside VPC
Delivery

Branch & env gates

  • main: CI quality + 1 review
  • Env prod: required reviewers
  • jhgcc1 (admin) may bypass; staging unprotected for velocity
